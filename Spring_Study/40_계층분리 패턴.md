# 40_계층분리 패턴

> Spring에서의 Layer Architecture

## 1. XxxService와 XxxWebService

스프링 프로젝트 코드를 보다보면 서비스 레이어에서 `XxxService`와 `XxxWebService`로 코드가 나눠진 것을 볼 수 있다.

이는 스프링 프레임워크에서 강제하는 규칙이 아니라, 계층 분리 패턴(레이어드 아키텍처)라고 한다.

조직/팀 컨벤션에 따라서 XxxWebService가 아니라 `XxxFacade`, `XxxApplicationService`로 명명하기도 한다.

### (1) XxxService

순수 비즈니스 로직과 도메인 규칙을 담당한다.

따라서 어떤 진입점(웹, 배치, 메세지 큐 등)에서 해당 서비스를 호출하든 동일하게 동작해야한다.

### (2) XxxWebService, XxxFacade

특정 채널(웹, 배치 등)에 특화된 오케스트레이션 계층.

여러 Service들을 조합하고, DTO ↔ 도메인 객체 변환 등, 특정 API가 필요로 하는 흐름과 로직을 조립하여 제공한다.

<br>

## 2. 분리 이유

이렇게 서비스 레이어를 계층화하는 핵심적인 이유는 **"하나의 도메인 로직은 여러 진입점에서 재사용될 수 있다"**는 문제에서 비롯된다.

즉, UserService에서 제공하는 특정 로직들은 REST API(웹)에서도 호출되어 사용될 수 있고, 배치 스크립트, 이벤트 리스너 등에서 호출되어 사용될 수 있다.

각 진입점마다 요구하는 사항이 일률적이라면 UserService 하나로도 충분히 처리 가능하겠지만, 실제론 그렇지 않다.

예를 들어, 웹 요청에서만 필요한 것들(특정 DTO 변환, 세션, 유효성 검사, 여러 도메인 서비스를 엮어서 하나의 API 응답 만들기 등)이 따로 있지만 이러한 것들은 배치나 이벤트 리스너에서는 불필요하며, 웹 관련 의존성이 있기 마련이다.

그래서

- Service: 채널과 무관하며 재사용 가능한 순수 도메인, 어플리케이션 로직 계층
- WebService, Facade: 특정 채널의 요구사항을 만족하기 위해 다른 도메인 서비스 혹은 기술 의존적인 코드를 조립하는 얇은 오케스트레이션 계층

으로 나누는 것이다.

### (1) 유의사항

- 진입점이 웹 하나뿐인 작은 규모의 프로젝트에서는 분리형 계층 구조를 채택하는 것은 오버엔지니어링일 수도 있음.
  - 확장 가능성이 없고, 하나의 컨트롤러에서 다수의 서비스를 호출해서 처리해도 무방하다면 굳이 계층/진입점을 하나 더 만드는 것은 낭비.
  - 여러 채널에서 재사용될 가능성이 높은 도메인이 있을 경우에 레이어드 아키텍쳐 형태로 분리하는 것이 가치가 있다.
- 오케스트레이션 계층에 가격 계산, 검증 로직 등 해당 도메인에 종속적인 비즈니스 로직/규칙을 넣으면 안 됨. 이렇게 하면 다른 진입점에서 이 로직을 사용할 수 없음. 오케이스트레이션 계층은 해당 진입점에서 관심있는 서비스들의 로직을 조합하는 역할만 하고, 판단은 하면 안 됨.
  - 가격 계산을 예를 들면, 배치로 주문을 생성하든, 관리자 생성하든, 이벤트로 주문이 생성되든 간에 가격이라는 요소는 항상 같은 규칙으로 계산되어야 함. 특별한 이유 없이(특정 진입점의 경우 할인 로직, 세율 적용 로직 다름 등) 여러 서비스에 동일한 불변 규칙을 가지고 있을 필요는 없음.
  - 재고 검증의 경우에도 어떤 진입점에서든 주문이 생성될 때, 재고가 없으면 실패해야만 함. 이를 특정한 오케스트레이션 계층에만 넣으면, 다른 진입점에서 주문을 생성할 때 재고 검증 로직이 누락되는 이슈가 발생할 가능성도 있음.

```java
// 도메인 검증 - "주문"이라는 개념 자체가 항상 지켜야 하는 규칙
@Service
public class OrderService {
    public Order createOrder(Long userId, List<OrderItem> items) {
        validateStock(items);       // 재고 없으면 어디서 호출되든 실패해야 함
        BigDecimal price = calculatePrice(items); // 가격 규칙도 항상 동일
        ...
    }

    private void validateStock(List<OrderItem> items) { ... }
    private BigDecimal calculatePrice(List<OrderItem> items) { ... }
}

// 웹 계층 - 형식적/전달 관심사
@Service
public class OrderWebService {
    public OrderResponseDto placeOrder(OrderRequestDto dto) {
        // 이건 "웹 요청 형식이 올바른가"에 대한 것 -> 도메인 규칙 아님
        if (dto.getItems() == null || dto.getItems().isEmpty()) {
            throw new InvalidRequestException("items는 비어있을 수 없습니다");
        }

        Order order = orderService.createOrder(dto.getUserId(), dto.toDomainItems());
        return OrderResponseDto.from(order); // 도메인 -> 응답 형태 변환
    }
}
```

## 3. 예시

### (1) Service

```java
@Service
public class OrderService {
    public Order createOrder(Long userId, List<OrderItem> items) {
        // 재고 확인, 가격 계산 등 핵심 비즈니스 규칙
        ...
    }
}

@Service
public class PaymentService {
    // 결제 로직
    public Payment processPayment(Order order) { ... }
}

@Service
public class NotificationService {
    // 주문 알림
    public void sendOrderConfirmation(Order order) { ... }
}
```

### (2) Orchestration

```java
// 주문을 생성하고 결제 후 알림을 보내는 주문결제 E2E 로직을 처리하는 오케스트레이션 계층
@Service // 또는 커스텀 @Facade 어노테이션 등
public class OrderWebService {

    private final OrderService orderService;
    private final PaymentService paymentService;
    private final NotificationService notificationService;

    public OrderResponseDto placeOrder(OrderRequestDto requestDto) {
        // 1. DTO -> 도메인 변환
        // 2. 여러 도메인 서비스 조합 (이 API에서만 필요한 흐름)
        Order order = orderService.createOrder(requestDto.getUserId(), requestDto.getItems());
        paymentService.processPayment(order);
        notificationService.sendOrderConfirmation(order);

        // 3. 도메인 -> 응답 DTO 변환
        return OrderResponseDto.from(order);
    }
}
```

### (3) Controller

```java
@RestController
public class OrderController {
    private final OrderWebService orderWebService;

    @PostMapping("/orders")
    public OrderResponseDto createOrder(@RequestBody OrderRequestDto dto) {
        return orderWebService.placeOrder(dto); // Controller는 위임만
    }
}
```
