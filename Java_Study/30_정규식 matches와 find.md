# 30_정규식 matches()와 find()

> Java Regex find() vs. matches()

자바의 정규식에서 해당 정규식과 매칭되는 패턴을 찾기 위한 목적의 메서드는 find()와 matches()가 있다.

두 메서드의 공통점은 `정규식 패턴과 일치하는지 확인`하는데 사용된다는 점이다. 이러한 점에서 어떤 상황에서 어떤 메서드를 사용해야 하는지 헷갈리기 쉽지만, 두 메서드는 명확한 차이점이 존재한다.

## 1. matches()와 find()

> matches(): 전체 매칭 vs. find(): 부분 매칭

### 1) matches()

대상 문자열 **전체**가 정규식 패턴과 일치해야 `true`를 반환하고, 일치하지 않으면 `false`를 반환한다.

별도의 앵커(`^`, `$`)가 없어도 내부적으로 대상 문자열의 시작~끝까지 전체를 검사한다.

- `^`: 문자열(또는 각 줄)의 시작
- `$`: 문자열(또는 각 줄)의 끝

#### (1) 목적

"이 문자열이 이 형식(패턴)과 완전히 일치하는가?"

즉, matches()의 목적은 검증(validation)에 있다. 특정 문자열이 이메일 형식인지, 혹은 숫자로만 이뤄져있는지, 비밀번호 규칙을 만족하는지 등 문자열에 대한 검증을 실시할 때 사용한다.

#### (2) 내부 동작

매칭의 시작 위치를 항상 문자열의 0번 인덱스에서 고정한 다음, 끝까지 소비(consume)했는지 확인한다.

항상 시작과 끝을 훑기때문에 전체를 보니까 부분 매칭인 find()에 비해 느리다는 오해를 하기 쉽다. 그러나 사실 항상 그런 것은 아니다.

- find()의 경우에도 만약 앵커(^, $)가 있다면 matches()와 동일하게 동작하기 때문에 기본적으로 O(n)이 소요될 수밖에 없다.
- Java 정규식 NFA 기반의 백트랙킹 방식의 엔진의 경우 나쁜 패턴(패턴의 모호성, 중첩 반복자 등)이 있을 경우 엄청나게 느려지는 성능 이슈가 발생하며 이는 find()도 마찬가지이다.
- find() 역시 매치를 못찾으면 시작 위치를 다음 인덱스로 옮긴 다음에 재시도를 하기 때문에 O(n^2)이 걸릴 수도 있다.

<br>

### 2) find()

대상 문자열 **일부**에서라도 정규식 패턴과 일치하는 부분(substring)이 있으면 `true`를 반환하고, 일치하지 않으면 `false`를 반환한다.

반복 호출할 경우 이전 매칭된 부분 이후부터 다음 매칭된 부분을 계속 찾아나간다.

#### (1) 목적

"이 문자열 안에서 이 형식(패턴)이 (찾을 수) 있는가?"

find()의 목적은 탐색(extraction)에 있다. 특정 문자열에서 형식(패턴)을 만족하는 문자열이 있는지, 또 몇 개 있는지 등을 파악하기 위한 목적으로 사용된다. 예를 들어 로그 텍스트에서 조건을 만족하는 IP 주소가 있는지 등을 찾기 위한 용도로 사용된다.

#### (2) 내부 동작

매칭의 시작 위치를 0에서 시작하지만 점점 슬라이딩(sliding) 방식으로 옮겨가며, 매칭되는 구간을 탐색하고 매칭이 발견되면 그 지점의 시작과 끝 인덱스를 Matcher 객체에 저장하여 start(), end(), group() 등으로 조회가 가능하게 해준다.

## 2. 정규식 매칭에 대한 오해와 올바른 접근법

### 1) 오해

#### (1) 정규식이 항상 좋다

"정규식이 항상 문자열 검색보다 유연하고 좋다" => X

아니다. 고정 문자열의 경우 contains()와 indexOf()가 항상 더 빠르다.

#### (2) 긴 텍스트는 자르는게 좋다

찾고자 하는 패턴이 단순할 경우에 길이는 문제가 될만한 요소가 아니다. 자르는 건 오히려 패턴을 못 찾는 버그를 발생시키는 안티 패턴이다.

<br>

### 2) 올바른 접근법

#### (1) 안전한 패턴 사용

패턴 자체를 안전하게 짠다. 즉, `(a+)+`, `(a*)*`, `(a|a)*`와 같은 중첩 반복자가 포함된 구조를 정규식 패턴으로 사용하지 않는다.

#### (2) 타임아웃 방어

Java 표준 정규식 엔진은 자체적으로 타임아웃 기능이 없기 때문에 정규식 패턴 검사 시 별도의 스레드에 작업을 할당하면서 타임아웃을 거는 방식으로 사용하는 것이 적절하다. 다만, future.cancel(true)를 할 경우 정규식 엔진 내부 루프를 즉시 멈추는 것을 보장하지 못하기 때문에 좀비 스레드가 될 수도 있음을 유의해야 한다.

#### (3) 백트랙킹을 사용하지 않는 정규식 엔진 사용

백트랙킹 알고리즘을 사용하지 않는 정규식 엔진을 사용할 경우 O(n)의 시간복잡도를 보장하여 안전할 수 있지만, 지원하는 정규식 문법이 제한적일 수밖에 없으니 유의.
